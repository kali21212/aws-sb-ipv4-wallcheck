AWS.SB IPv4 WallCheck Portable 2.0.1
==================================

一、功能和版本
浏览器扩展 2.0.1；本机探针内核保持 1.6.1，两者兼容。
支持 Windows 10/11 x64 和 Chromium 系浏览器，例如 Edge、Thorium。
本机同时检测 IPv4 的 ICMP Ping 与 TCP 22，不会探测 IPv6 或其他端口。
IPv6 文字只可能用于区分 EC2 实例身份，不作为网络检测目标。

二、启动与安装扩展
1. 将便携 ZIP 完整解压到固定目录，不要在压缩包里运行。
2. 运行包内启动检测的 CMD。源码目录对应“启动 WallCheck.cmd”。
3. 打开浏览器扩展管理页，启用开发者模式，选择“加载已解压的扩展”。
4. 选择解压目录中的 browser-extension 文件夹。
5. 打开自己的 AWS.SB EC2 实例页面；页面须包含有效 sgt 才能隔离账号。
6. 面板应显示“IPv4 WallCheck 2.0.1”和实际检测状态。
升级现有目录后，在扩展管理页点“重新加载”，再刷新已打开的 AWS.SB 页面。
保留原扩展路径和浏览器配置，不要先删除扩展，否则可能丢失本地历史。

三、自动检测间隔
默认每 5 分钟检测。面板“自动检测间隔”可以输入 1～60 的整数分钟，
点击“保存”或按 Enter 后立即调整后续计划，无需重启电脑。
例如希望 3 分钟一次，输入 3 并保存即可。
设置保存在当前浏览器配置中；刷新页面、重启浏览器后继续使用。
同一浏览器配置的所有 AWS.SB 页面共享此设置；不同浏览器配置相互独立。
“强制重测”立即进行一次新的 Ping + TCP22 检测。
手动 IP 监控另有每个目标的 1/5/10 分钟设置，不受本项影响。

四、时间与颜色含义
“上次实测 HH:mm:ss”是最近一轮实际检测完成时间，不是页面刷新时间。
“缓存结果（未重测）”保留原实测时间，不表示刚刚重新测过。
部分目标没有有效结果时显示“本轮实测”和已验证数量，15 秒后补测。
探针通信失败会单独显示本轮失败时间；旧有效结果不会假装是新结果。
绿色：Ping 可达且 TCP22 可达。
红色严重告警：Ping 或 TCP22 任一实测失败；两者失败也为红色。
Ping 无回应不等于 SSH 一定故障，提示会区分失败项目。
未知或未验证结果不作为已证实的目标故障。
同一种持续故障按一个事件去重，恢复后再次失败会生成新事件。
本机网络检测不等于绝对的“被墙”结论。

五、IP变化、账号故障与历史
不同 sgt 账号的实例、变化和确认状态分开保存。
同一实例或同一监控组实际观察到旧 IP → 新 IP 时记录变化并检查新 IP。
“已知”确认对应事件或整组变化，不会清除其他账号的记录。
历史目标未出现在本页，是独立信息提示，不代表它已离线。
账号失效会记录事件；替补后须有实际可达证据才记录恢复。
关闭页面或电脑期间没有观察到的 IP/账号变化不能补造历史。

六、Windows系统通知
点击面板“测试通知”。提示“已提交浏览器通知”说明浏览器接受请求；
仍需看到桌面通知才能确认 Windows 实际显示。
检查 Windows 通知、勿扰模式及浏览器通知设置；页内告警保留作为提示。
便携包包含系统通知辅助程序。登录自启是可选设置，按包内对应 CMD 操作。
已有 Guardian 会检查本机探针健康；它的保活间隔与页面检测间隔不同。

七、2.0.1修复内容
检测未结束时切换账号、离开 EC2 页面或替换 IP，会丢弃旧页面的迟到结果。
旧结果或旧通信错误不会冒充新页面的检测完成时间，也不会提交给新账号。
多个页面同时完成检测时，在后台按账号合并结果，不再覆盖其他页面的缓存。
清空本页记录会使在途的旧缓存失效；其他账号、已保存检测间隔不受影响。

八、运行边界与维护
页面监控需要浏览器运行并保持相关 AWS.SB 页面打开。
浏览器关闭、电脑休眠或系统调度延迟期间不能保证按时检测。
手动 IP 监控不需要 AWS.SB 页面，但仍需要浏览器与本机探针运行。
探针健康接口：http://127.0.0.1:17654/healthz
本机探针仅监听 127.0.0.1:17654，不应向局域网或公网开放。
分发包不应包含账号、Cookie、sgt、浏览器配置、个人 IP 历史或日志。
不要把现用完整目录直接压缩发给别人；使用已清理的正式便携包。
